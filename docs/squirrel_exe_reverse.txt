SquirrelReceiver.exe — notes from the binary and the wire
=========================================================

PE64, ~28 MB, MD5 1661d3520247efddce2576f02a5fa4e4.
The Store binary is not in this repo (copyright, size). Strings / VAs
for this hash: docs/squirrel_rdata_dump.txt. Open your own copy if you
want the file.

Captured against live Goggles 3. Where the UI and the UDP disagree, the
UDP wins.


0. Build leftovers
------------------

Release still contains Cargo registry paths:

    C:\Users\Ich\.cargo\registry\src\index.crates.io-...

Debug panic paths + a Windows profile name in a Store build. Build
hygiene, not a protocol secret. “Author” below = whoever shipped this
exe. Not DJI.


1. What the binary actually is
------------------------------

Microsoft Store GUI (eframe/egui + wgpu + gstreamer-rtsp) on the same
open UDP liveview the goggles already share.

No session key. No HMAC. Header byte 7 is XOR of bytes 0..6.
48-byte handshake is a literal in rdata @ 0x141543120; only session
u16 is patched.

Edition UI lives in compositor overlays, not on the socket:

    src\ui\activation_overlay.rs
    src\ui\demo_watermark_overlay.rs
    src\entitlement\store.rs
    src\h264_bootstrap_image.rs     — decoder workaround, §6

DEMO vs ACTIVATED does not change handshake, ACK, or type-2. LUT /
record / 4:3 gates are local. The wire does not care.

Hence the embedded HTML manuals

4. UDP header — protocol.rs
---------------------------

8 bytes LE.

    0  u16  length | 0x8000
    2  u16  session
    4  u16  seq
    6  u8   type
    7  u8   xor(b[0]..b[6])

XOR mismatch → drop. (len & 0x7FFF) != datagram size → drop.

    0 handshake   1 data   2 video   3 file   4 ACK   5 cmd   6 ack2

Type-2 seq += 8. Type-2 seed = u16 at offset 8 of type-0.


5. Handshake template @ 0x141543120
-----------------------------------

    30 80 3A DD 00 00 00 57 D0 E9 64 00 64 00 C0 05 14 00 00 0A 00
    64 00 64 00 C0 05 14 00 00 64 00 14 00 64 00 C0 05 14 00 00 64
    00 01 01 04 0A 02

session in [2:4], xor in [7]. Repeat type-0 until type-1/2.
Their log: “startup probe timed out after N handshakes”.


6. Video — parse_video, reassembly, bootstrap
---------------------------------------------

    +0x10 frame
    +0x11 n_parts / part
    +0x14 Annex-B

G3 liveview is High Profile with almost no IDR. VideoToolbox and
ffplay-as-h264 stall or smear. The binary already says so:

    preview injected H.264 bootstrap after ... without real IDR;
    dropped ... held AUs ... and released current AU

    Recording injected H.264 bootstrap after ...

    src\h264_bootstrap_image.rs

They inject a synthetic bootstrap AU into preview and recording, and
drop/hold access units around it, because the demuxer wants a RAP.
That is a local decoder hack. It is not an IDR from the goggles. Files
written that way are not a clean Annex-B capture.

This lab: libav FLAG2_SHOW_ALL + LOW_DELAY for the window; disk output
is the type-2 payload as received. No synthetic IDR in --out.


7. ACK — build_ack
------------------

No type-4 → stream dies. Overlay can still look “connected”.

    [8]  win2 start/end
    [12] resend_count
    [14] resend[]
    then type3/type5 windows, optional DUML (bitrate hint piggy-back)

Keepalive ~30 Hz here (--ack-interval 1/30). Optional --ack-every on
each type-2. Their “Wi-Fi ACKs” / “stopping Wi-Fi ACKs” are type-4.


8. rtx.rs vs the UI toggle
--------------------------

Seq step 8. Goggles ignore the entire resend list unless it starts at
the first hole. Documented in their rtx.rs; enforced by firmware.

UI:

    Loss recovery: ON / OFF

ON only means “put missing seqs in the ACK”. Wrong order, or list not
starting at the first gap → zero recovery while the label stays ON.
That is a UI/protocol mismatch, not RF.

Retransmit is still NACK, not FEC. Goggles may not resend.


9. type-1 / DUML
----------------

~10 Hz. Windows + DUML at [34]. CRC8 seed 0x77, CRC16 seed 0x3692 —
public DJI tables. sender 0x1B goggles, 0x02 app.


10. type-5
----------

Command wrapper, seq step 8. If MI04 is not claimed, the bitrate DUML
goes here (boost_via=udp). Fallback, not a second bitrate protocol.


11. MI04 / bitrate.rs / worker.rs
---------------------------------

    USB\VID_2CA3&PID_0020&MI_04
    ff/43/01 bulk

Claim interface 4. Do not set_configuration, do not reset — that kills
RNDIS.

    sender 0x1B  recv 0xEE  cmdset 0x51 cmd 0x29
    payload ebfeefbe03000f000201010000000001000000 + u32le kbps
    default 22500 (0x57E4) every 250 ms (0xFA)
    UI min 22000 (0x55F0)

Strings:

    Bitrate boost (experimental)
    Bitrate boost active: feedback= kbps interval= ms
    Bitrate boost stopped; DJI adaptive bitrate will resume
    DJI USB control driver is not installed

The packet is real. The name “boost” is not a lock: it is a periodic
bitrate report/hint. When it stops, their own log says DJI ABR resumes.
If the USB control driver is missing, they have no MI04 and the hint
never lands on if 4.


12. Receive loop
----------------

    bind UDP (0.0.0.0 or 192.168.60.1)
    type-0 to wifi and/or wired until linked
    type-1 → telemetry ACK
    type-2 → assembler, RTX gaps, ACK at end of frame
    1s without video → stalled, reset loss window
    boost: try Mi04.open every 2s, else type-5
    burst recv — one recvfrom per loop drops 1080p on RNDIS

Their: “liveview probe has no bound socket; restarting source search”.
Usually no NIC / no RNDIS / wrong bind, not a mystery probe.


13. Edition gates (local only)
------------------------------

    LUT enable blocked by edition/access gate
    Lens 4:3 expansion blocked by edition/access gate
    Lens correction enable blocked by edition/access gate
    Recording arm blocked by edition/access gate
    Enable RTSP
    Demo mode is limited to 5 minutes

Same UDP for demo and paid. LUT is a .cube in the compositor. 5-minute
demo is a timer on the GUI.

Here LUT / 4:3 / MPEG-TS are optional local ffmpeg filters. Not an
edition.


14. goggles_adapter.rs
----------------------

Windows inbox RNDIS. No macOS driver in the exe; HTML for manual IP.
“The goggles adapter was configured, but the goggles did not respond
on the wired link” — typically IP on the wrong adapter, or OTG on
(goggles become USB host → this is method 1, not :9003).

This binary is IP liveview only. No AOA gadget path in the strings
that matter.


15. Short
---------

- Session id is a u16; integrity is XOR-7.
- Handshake is a 48-byte constant.
- Cargo home path leaked in the Store build.
- No RAP on the stream; they inject a bootstrap AU locally.
- RTX list must start at the first hole or firmware drops it; UI ON
  does not imply recovery.
- Store build cannot set 192.168.60.1; manuals are inside the exe.
- Bitrate DUML is experimental feedback; ABR remains in charge.
- Endpoint strings are concatenated without a separator.
- No Mac RNDIS stack in this product.

ip-liveview/ (C g3lv, Python notes) speaks the same UDP. It is not a
repack of the Store app.
