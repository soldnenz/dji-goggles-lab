SquirrelReceiver.exe — полный разбор (Goggles 3 IP liveview)
============================================================

Windows Store GUI на Rust. UDP :9003 на DJI Goggles 3, когда они жмут
Share Live View. Сам .exe в git не клал — копирайт, и так всем понятно
откуда константы.

Снимал с rdata + Wireshark на живых G3. Если бинарь и очки спорят —
верю очкам, не автору.

Только Goggles 3. G2 / Integra сюда не прикручивал.


1. Как вскрывал
---------------

PE64, Rust, в rdata до сих пор торчат пути:

    src\protocol.rs
    src\rtx.rs
    src\device_control\mi04.rs
    src\device_control\bitrate.rs
    src\entitlement\mod.rs
    src\entitlement\store.rs
    src\ui\activation_overlay.rs
    src\ui\app
    src\engine\rtsp_streaming.rs

VA с того билда (ASLR, себе перебазируй):

    0x141543120    шаблон type-0 handshake, 48 байт
    0x14026A1A0    bitrate.rs  mov r8d, 0x57E4  ; 22500 kbps
                   на стеке интервал 0xFA = 250 ms

Рядом в ASCII:

    192.168.2.1
    192.168.60.2
    9003
    DEMO MODE
    ACTIVATED
    ACTIVATION REVOKED
    STORE LICENSE NOT VERIFIED
    LUT enable blocked by edition/access gate
    Recording arm blocked by edition/access gate
    Lens 4:3 expansion blocked by edition/access gate

Windows HWID:

    USB\VID_2CA3&PID_0020&MI_04

Проверка: Wireshark на AP очков (192.168.2.0/24) и на RNDIS
(192.168.60.0/24). Handshake, type-2, type-4 совпали с rdata.
То есть я не «угадал протокол по скриншоту стора».


2. Что это за программа
-----------------------

Скин Microsoft Store вокруг открытого UDP.

Нет session key. Нет HMAC. Байт 7 хедера — XOR первых семи. 48-байтовый
handshake лежит литералом в rdata, патчится только session u16.

Дальше они наклепали:

    activation_overlay.rs    DEMO / ACTIVATED / REVOKED
    entitlement\store.rs     LUT, запись, 4:3, RTSP за гейтом
    bitrate "boost"          23 байта DUML на MI04, без шифра
    RNDIS только Windows     на маке тот же 8-байтный хедер
                             приходится поднимать через tetherkit

Пейвол в композиторе. Сокету плевать. Красиво для стора, стыдно для
протокола.


3. Сеть
-------

    вход                         очки                     ты
    ---------------------------  -----------------------  ----------------------
    Wi-Fi "share to phone"       192.168.2.1:9003         DHCP с SSID очков
    USB Remote NDIS (Win)        192.168.60.2:9003        192.168.60.1/24, без gw
    USB на macOS                 то же                    tetherkit-cli -> feth0

Только UDP. Они шлют на 9003 очков. Бинд 0.0.0.0 или 192.168.60.1
для кабеля.

OTG на очках = метод 1 (телефон/gadget). Для этого UDP OTG выкл,
G3 остаются USB device (RNDIS). Перепутаешь — я уже писал в README.


4. UDP header (каждый пакет, 8 байт, LE)
----------------------------------------

    off     тип    поле
    0       u16    length | 0x8000      бит 15 всегда
    2       u16    session
    4       u16    seq
    6       u8     type
    7       u8     xor(bytes[0..7))     xor первых 7 байт

Не сошёлся xor — дропай. (length & 0x7FFF) != размер — дропай.

    type  имя
    0     handshake
    1     data / windows / DUML
    2     video
    3     file
    4     ACK (клиент -> очки)
    5     command
    6     ещё ACK

Type-2 seq шагает на 8 (младшие 3 бита 0). Сид для type-2 — u16 на
offset 8 в type-0.


5. Type 0 — handshake (48 байт)
-------------------------------

Шаблон из rdata @ 0x141543120:

    30 80 3A DD 00 00 00 57
    D0 E9 64 00 64 00 C0 05
    14 00 00 0A 00
    64 00 64 00 C0 05 14 00
    00 64 00 14 00
    64 00 C0 05 14 00 00 64
    00 01 01 04 0A 02

    30 80          length 0x0030 | 0x8000
    3A DD          session 0xDD3A в шаблоне
    00 00          seq
    00             type 0
    57             xor предыдущих семи
    D0 E9          seed 0xE9D0  (с этого шаблонного session
                   стартует type-2; мы патчим session и xor)

Сборка:

    скопировать шаблон
    session в [2:4]
    length|flag в [0:2]
    byte[7] = xor(byte[0] .. byte[6])

Клиент долбит type-0 пока не придут type-1/2. Крипты нет. Вообще.


6. Type 2 — видео
-----------------

    off     поле
    0..7    header
    8       u16 window_start
    10      u16 window_end
    0x10    u8  frame index
    0x11    n_parts в младших 7, part упакован с 0x12
    0x14    H.264 Annex-B   VIDEO_HEADER = 0x14

    part    = (b[0x11] >> 7) | ((b[0x12] & 0x1F) << 1)
    n_parts = b[0x11] & 0x7F

Склеить части 0 .. n_parts-1 одного frame, concat H.264.

G3 liveview = High Profile, длинные P-slice, IDR почти нет.
Железо которое ждёт RAP — висит. Их Windows «просто работает»,
потому что внутри уже SHOW_ALL (или аналог). Они это нигде не
написали. Люди неделю ковыряют USB. Я тоже ковырял. Потом открыл
декодер и стало смешно.


7. Type 4 — ACK (без него стрим дохнет)
---------------------------------------

Перестал слать type-4 — источник сдох. Оверлей может дальше писать
ACTIVATED. Второго keepalive нет.

    off             поле
    0..7            header, type=4, seq обычно 0
    8               u16  type2 window_start
    10              u16  type2 window_end
    12              u16  resend_count
    14              u16  resend[0]
    14+2*n          ...
    дальше          u16 type3_start, type3_end, u16 zero
    дальше          u16 type5_start, type5_end, u16 zero, u16 zero,
                    u16 duml_len
    дальше          опциональный DUML

Resend = пропущенные type-2 seq, по дырам, шаг 8.
СПИСОК ИГНОРИТСЯ ЕСЛИ НЕ НАЧИНАЕТСЯ С ПЕРВОЙ ДЫРЫ.

Это у них в rtx.rs. UI орёт Loss recovery. Перемешал список или
начал не с первой дыры — G3 кидает ACK целиком, «рандомные» артефакты
на Wi-Fi. Очки буквальные. Клиент кривой. Автор, ну серьёзно.


8. Type 1 — data
----------------

~10 Hz после хендшейка.

    [8]    u16 window_start
    [10]   u16 window_end
    [0x10] type3 window
    [0x18] type5 window
    [32]   u16 duml_len
    [34]   DUML (0x55 ...)

DUML v1: 0x55, длина в младших 10 битах u16@[1], CRC8 первых 3 байт
@[3] seed 0x77, CRC16 body seed 0x3692. Те же таблицы что у всего DJI
MB за последние лет десять. Не секрет.

    sender 0x1B = goggles
    sender 0x02 = app
    cmdset 0x00 general, 0x02 camera, 0x51 на MI04 boost, ...


9. Type 5
---------

Обёртка команд. Seq шаг 8 как type-2. Сначала два window, потом
counter, 0x01 0x00 0x00, потом DUML.


10. MI04 bitrate (USB, не UDP)
------------------------------

Композит 2CA3:0020

    if 0,1    RNDIS           Windows inbox / tetherkit на маке
    if 4      vendor ff/43/01 bulk OUT+IN     "MI04"

TetherKit забирает 0+1. If 4 не трогать конфигом: claim_interface,
НЕ set_configuration, НЕ reset — иначе RNDIS отвалится. Если их
boost-воркер ресетит весь композит, это баг который они выкатили
в стор. Не я.

DUML на MI04 (bitrate.rs):

    sender     0x1B
    receiver   0xEE
    cmdset     0x51
    cmd        0x29
    payload    eb fe ef be 03 00 0f 00 02 01 01 00 00 00 00 01 00 00 00
               + u32le kbps   (по умолчанию 22500 = 0x57E4)
    период     250 ms (0xFA)

Их UI-минимум 22000 (0x55F0). Это report битрейта, не лицензия.
Шлёт кто угодно.


11. CRC (DUML)
--------------

CRC8 seed 0x77, CRC16 seed 0x3692. Таблицы публичные, те же что в
protocol.py. Это не ключ и не «наша крипта».


12. Ошибки exe, по тому сколько времени они сожрали
---------------------------------------------------

1. Handshake — константа. Оверлей делает вид что сессия лицензирована.
   Это XOR-7. Я бы постеснялся.

2. RTX работает только если первая missing seq первая в списке.
   Сами написали в rtx.rs. UI всё равно врёт.

3. High Profile без IDR. Декодер ждали «нормальный live H.264».
   Нет. FLAG2_SHOW_ALL или чёрное окно и нытьё про кабель.

4. ACK и есть сессия. Снял ACK — стрим мёртв, оверлей зелёный.

5. MI04 + RNDIS на одном композите. Reset/set_config с boost убивает
   NIC. Тестили на винде с inbox RNDIS и никогда не клеймили if 4
   параллельно без bus reset. Видно.

6. Гейты LUT / record / 4:3, при этом на проводе DEMO и ACTIVATED
   одинаковые. Кто взял exe как спеку «что очки разрешают» — взял
   не тот слой.

7. Нет Mac RNDIS. Выкатили Store-апп, не спеку протокола. Из-за этого
   на Darwin тот же хедер через userspace Ethernet. Не гордость
   экосистемы, просто лень.
