4. UDP header — protocol.rs / pack_header / parse_header / xor7
---------------------------------------------------------------

8 байт LE.

    0  u16  length | 0x8000
    2  u16  session
    4  u16  seq
    6  u8   type
    7  u8   xor(b[0]..b[6])

Не сошлось — мусор. (len & 0x7FFF) != размер — мусор.

    0 handshake   1 data   2 video   3 file   4 ACK   5 cmd   6 ack2

Type-2 seq += 8. Сид type-2 = u16 @ offset 8 в type-0.

7. ACK — build_ack, keepalive
-----------------------------

Без type-4 стрим дохнет. Оверлей зелёный.

    [8]  win2 start/end
    [12] resend_count
    [14] resend[]
    потом окна type3/type5 и опциональный DUML (туда же пихают boost)

9. parse_data / parse_duml / type-1
-----------------------------------

~10 Hz. Окна + DUML @ [34]. CRC8 seed 0x77, CRC16 0x3692 — публичные
таблицы DJI. Не твоя крипта. sender 0x1B очки, 0x02 app.


10. build_type5
---------------

Обёртка команд, seq шаг 8. Если MI04 не открылся — boost уходит
сюда (у меня boost_via=udp). Костыль. У автора на винде «должен»
быть MI04.


11. Mi04 / bitrate.rs / worker.rs
---------------------------------

    USB\VID_2CA3&PID_0020&MI_04
    ff/43/01 bulk

Claim if 4. НЕ set_configuration, НЕ reset — иначе RNDIS умрёт.

    sender 0x1B  recv 0xEE  cmdset 0x51 cmd 0x29
    payload ebfeefbe03000f000201010000000001000000 + u32le kbps
    default 22500 (0x57E4) каждые 250 ms (0xFA)
    UI min 22000 (0x55F0)

Строки:

    Bitrate boost (experimental)
    Bitrate boost active: feedback= kbps interval= ms
    Bitrate boost stopped; DJI adaptive bitrate will resume
    DJI USB control driver is not installed

Experimental в сторе. Адаптивный битрейт DJI «resume» — значит ваш
boost это не управление, а тыканье палкой в MI04. Store ещё и
драйвер USB control может не встать. Продукт года.


12. Session.run — как крутится приём
------------------------------------

    bind UDP (0.0.0.0 или 192.168.60.1)
    handshake на wifi и/или wired пока нет линка
    type-1 → telemetry ACK
    type-2 → assembler, RTX gaps, ACK на конец кадра
    timeout 1s без видео → stalled, LossWindow.reset
    boost: пробуем Mi04.open каждые 2с, иначе type-5
    recv_burst — не по одному recvfrom, иначе 1080p на RNDIS сыпется

У них: «liveview probe has no bound socket; restarting source search»
— сокет не биндится, они рестартят поиск. Я хотя бы пишу «кабель /
RNDIS нет», а не прячу за probe.
